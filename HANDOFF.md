## 4. Rules (non-negotiable)

1. **Sources.** Every number is either cited to a key in `references/references.bib` (added through `references/refs_*.psv` and `make refs`, which also checks that every cited key exists and every key is cited) or computed by tested code. Never invent a number, a citation, a price, or a photo. If a value cannot be sourced, say so and add it to `docs/STATUS.md`.
2. **Labels.** Mark each claim as demonstrated (measured and published), reported (vendor or news claim), simulated (this package), or proposed (this project's idea). Illustrative model inputs are labeled illustrative.
3. **Equations** state their assumptions and range of validity; the labs check them live.
4. **Tests and CI stay green** on Python 3.10 and 3.12. Compare floating-point golden values with a relative tolerance (1e-9), never exact equality.
5. **Regenerate, never hand-edit** generated files (`docs/build/*.md`, `docs/VALIDATION.md`, `docs/experiments/EXPERIMENTS.md`, `docs/GLOSSARY.md`, `docs/EQUATIONS_IN_ACTION.md`, the README key-findings table, `paper/numbers.tex`, golden JSON files).
6. **Design:** 60 frames per second, WCAG AA contrast, full keyboard operation, `prefers-reduced-motion` respected, no emoji icons, no gradient text, no text over plotted data (see `docs/DESIGN.md`).
7. **Photos:** only openly licensed images (public domain, CC0, CC BY, CC BY-SA) with source URL, author, license, and date recorded in a machine-readable credits file (see section 7). Never use AI-generated images presented as photographs. Diagrams are labeled as diagrams.
8. **Owner's preferences:** write acronyms out in full the first time, with the acronym in parentheses; be concise, direct, and precise; give Ubuntu (WSL2) terminal commands for every step the owner runs; English resources only.
9. **Review gates:** propose a plan before large changes; stop after each release for the owner's approval.

## 6. The next program: room-temperature quantum devices

### 6.1 Goal

Show, honestly and step by step, how the building blocks of a room-temperature quantum processor in diamond are made, characterized, and combined, so that quantum computing could scale without dilution refrigerators. Superconducting transmon qubits need about 10 to 20 millikelvin; NV centers in diamond keep spin coherence at room temperature. The gaps that decide whether room-temperature machines can compete are already modeled in ADAMAS (two-qubit fidelity, readout, placement yield, the inter-cell link: `docs/expert/E5`, `E6`, `E10`, `adamas/gate_budget.py`, `adamas/resource.py`); the new work turns them into devices, processes, and manuals. The superconducting operating temperature and every comparison number must be cited when written into the repository.

### 6.2 The owner's words, mapped to physics

The owner asked for "quantum transistors, resistors, etc.". There is no standard device by those names. Treat them as **analogies** that help readers, and give each one a precise definition. Use the analogy name in the user interface only next to the real name, and never claim a device that the literature has not shown. A proposed mapping, which the agent must source or correct before shipping:

| Classical analogy (label only) | Room-temperature quantum building block in diamond | What it does | Where ADAMAS already covers it |
|---|---|---|---|
| Memory bit cell | **Qubit cell**: a single NV center (electron spin) with its optical access and microwave drive | Stores and rotates one qubit | `nv`, `photophysics`, Qubit and Photon Labs, experiment C1 |
| Register or long-term memory | **Nuclear-spin memory**: ¹⁴N, ¹⁵N, or ¹³C spins next to the NV | Holds quantum states for much longer than the electron | `register`, E5 |
| Transistor (the switching element) | **Two-qubit coupler**: two NVs a few to tens of nanometres apart, coupled by the magnetic dipole interaction, giving a controlled-phase gate | Makes one qubit's state control another's | `coupling`, `gate_budget`, `addressing`, `gatebias`, experiment D1 |
| Sense amplifier | **Readout cells**: optical readout, spin-to-charge conversion, and photoelectric readout through electrodes | Turns a spin state into a classical signal | `photophysics`, E5, chapter 9 |
| Wire, bus, or clock line | **Microwave drive line** (coplanar waveguide or stripline) and **optical waveguide** | Delivers control pulses and light | traveler metal steps, E2 |
| Interconnect between chips | **Photon emitter and link**: NV or group-IV color centers coupled to waveguides or cavities, entangling distant qubits | Connects qubit cells across a chip and between chips | `resource.LINK` (proposed), E10 |
| Gate electrode or bias | **Charge-control electrodes** that keep the NV in its negative charge state | Stabilizes the qubit | photophysics, E5 |
| Resistor (a dissipative element) | **Optical reset / polarization**: green light pumps the spin to mₛ = 0, a controlled loss of quantum information used for initialization | Resets a qubit | `photophysics` |

For each building block, the Quantum Device Library entry must give: function; physics and equations with assumptions; demonstrated, reported, simulated, or proposed status with sources; the device's figures of merit (coherence, gate fidelity, readout fidelity, footprint, yield) with sourced current values and target values; the fabrication route as steps of the process traveler (`adamas/traveler.py`) and machines from the Atlas list (`docs/phase0/BUILD_PROGRAM_OUTLINE.md`); a characterization checklist; simulated expected data; pass/fail criteria computed by code; and its failure modes.

**v0.32.0 · Fab Journey (website flow and PDF manuals)**
- Four scope levels, chosen on the first screen:
  - **Level 0, kitchen table:** see an NV ensemble glow and resonate (experiments A1, A2); no fabrication.
  - **Level 1, teaching lab:** pulsed control, vector magnetometry (B1–B3).
  - **Level 2, cleanroom device:** one qubit cell and a coupled pair: substrate inspection, cleaning, nitrogen implantation through a mask, vacancy creation, annealing, surface termination, electrodes and microwave line, packaging (traveler qubit variant S01–S19).
  - **Level 3, wafer scale:** growth, placement arrays, statistical process control, yield (D2, P7).
- Each step is one screen and one PDF page in LEGO-instruction style:
  - a parts box (materials, tools, chemicals with Atlas IDs);
  - the step number and a single action in one short sentence;
  - a large diagram (cross-section before and after, drawn to a stated scale or marked "not to scale");
  - a strip of real photographs (openly licensed, credited) of that tool or that kind of sample;
  - a checkpoint stating what you should see and how to measure it, with pass/fail;
  - safety callouts (chemicals, lasers, high voltage, vacuum, ion beams);
  - time and cost;
  - troubleshooting.
- One source drives both outputs: a Python step registry (extend `adamas/traveler.py`) renders the web flow and, through Playwright print-to-PDF (or Typst), the PDF manuals. CI builds the PDFs as release assets.
- Progress saved locally, printable checklists, a run log export (the traveler page already has one).

**v0.33.0 · Characterization and experiment manuals (nanometre-scale process)**
- Manuals in the same LEGO style for each measurement: implantation depth and straggle (Stopping and Range of Ions in Matter (SRIM) style range tables, extending `coupling.implant_rule_of_thumb`), secondary-ion mass spectrometry (SIMS) depth profiles, atomic force microscopy (AFM) of masks and apertures, Raman and photoluminescence (PL) mapping, NV conversion yield counting, optically detected magnetic resonance (ODMR), second-order correlation g⁽²⁾, Rabi, Ramsey, Hahn echo, T₁, dipolar-coupling spectroscopy of pairs, and readout fidelity.
- Each manual: purpose, equipment (Atlas IDs), sample preparation, numbered steps, simulated expected data, a fit in the Data Lab, the pass/fail criterion computed like `build_program.p2_*`, and failure modes.
- "Recreate it" kits: for each published experiment that ADAMAS uses as a reference point (validation matrix, chapters 7 and E5), a manual to reproduce it, with what to compare against.

**v0.34.0 · Graphics, interactivity, and the desktop app**

### 6.4 Things to be careful about

- Room-temperature two-qubit gates between NVs are demonstrated with modest fidelity; the best published room-temperature NV-NV entanglement in the repository's references is 0.82 [dolde2014], and the model in this repository does not yet explain the measured 0.67 [dolde2013] (validation matrix). Do not imply that room-temperature devices already match superconducting ones.
- Sub-diffraction addressing, deterministic placement, and scalable readout are open problems; present them as such (chapter 7, `docs/AUDIT.md` section 2c).
- Fabrication steps involve hazardous chemicals (hydrofluoric acid, piranha, perchloric acid), Class 3B and 4 lasers, high voltage, ion beams, and vacuum. Manuals give safety callouts and point to institutional training; they never replace it.

## 8. How releases work (the owner's machine)

The owner works in WSL2 Ubuntu on `Aleksander-Desk` (user `aleks`), repository at `~/projects/adamas-diamond-framework`, conda environment `adamas`, Windows Downloads at `/mnt/c/Users/aleks/Downloads/`. Pushing uses the SSH alias `github-normansrule`.

Each release is a branch `claude/vX.Y.Z` pushed to GitHub plus an apply script `apply-vX.Y.Z.sh` the owner runs. The script, following `apply-v0.30.sh`:
1. Activates the environment, switches to `main`, pulls, and checks that the current version is the previous release (stops otherwise).
2. Creates `feature/vX.Y.Z`, takes the tree of `origin/claude/vX.Y.Z` (fallback: a patch file in Downloads).
3. Installs (`pip install -e ".[dev]"`, `cd web && npm ci`), runs `make refs`, `python -m pytest -q -rs`, regenerates (`python -m adamas build docs`, `make figures animations`, `python -m adamas.paper`, `make paper talk poster`), builds and smoke-tests the site, runs the desktop self-test.
4. Commits, pushes, opens a pull request, squash-merges, tags, and creates the GitHub release (the desktop workflow then attaches installers).

Version is bumped in `adamas/__init__.py`, `pyproject.toml`, `CITATION.cff` (with `date-released`), and `desktop/package.json` (then `npm install --package-lock-only`). Add a row to `CHANGELOG.md` and update `docs/STATUS.md`.
